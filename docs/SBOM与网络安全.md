## 2. 已实现的网络安全控制措施

| # | 控制措施 | 实现 | 状态 |
|---|---------|------|------|
| N-1 | **导入输入校验**：拒绝目录、空文件、超大文件、畸形行 | `MainWindowQml::importHistory()` + `HistoryRecorder` | ✅ 部分（见说明） |
| N-2 | **导入路径固定**：只读 `<应用目录>/imports`，不接受任意路径 | 同上 | ✅ |
| N-3 | **无原生文件对话框**：避免通过对话框选择任意系统路径 | 文件头注释（`QGuiApplication` 约束） | ✅ |
| N-4 | **导出路径固定**：只写 `<应用目录>/exports` | `MainWindowQml::exportChartImage/exportHistoryData` | ✅ |
| N-5 | **审计日志行内 CRC32**：检测意外损坏与单行改动 | `AuditLogger` | ✅ |
| N-6 | **审计日志追加写入**：不覆盖历史记录 | `QIODevice::Append` | ✅ |
| N-7 | **越权操作留痕**：配置变更逐字段记录旧值 → 新值 | `MainWindowQml::auditConfigDiff()` | ✅ |
| N-8 | **QML 引擎不加载外部内容**：QML 文件全部编译进资源（`qt_add_qml_module`），不加载磁盘 / 网络上的 QML | `CMakeLists.txt` | ✅ |
| N-9 | **无网络通信**：不监听端口、不发起连接 | 全工程无 `QTcpSocket` / `QNetworkAccessManager` | ✅ |

### 2.1 相对 Widgets 版的**能力回退（必须记录）**

| 能力 | Widgets 版 | QML 版 | 影响 |
|------|-----------|--------|------|
| SHA-256 伴生清单（导出时生成、导入时校验） | `FileIntegrity` | ❌ **未移植** | 无法检出「数据被改动且清单未更新」 |
| 导入完整性阻断 | 哈希不符即拒绝 | ❌ **未移植** | 只能靠格式解析失败兜底 |
| 角色 / 权限分级 | `UserRole` + `ensurePermission()` | ❌ **未移植** | 任何人可改报警限 |
| 路径穿越净化 | `sanitizeFileName()` | ❌ 未移植（但路径本身固定，风险受控） | 导出文件名不可由用户输入 |

> 这一节的存在意义：让评审者不会因为「文档写了网络安全」而误以为
> 「这些控制措施都实现了」。**QML 版目前的网络安全能力只有「固定路径 +
> 审计留痕 + 无网络」三项**，完整性校验与权限体系均未落地。

### 2.2 控制措施的能力边界

| 能力 | 能防 | 不能防 |
|------|------|--------|
| 固定导入导出目录 | 误选到系统目录、路径注入 | 有人直接把恶意文件放进 `imports/` |
| CRC32 审计校验 | 意外损坏、单行改动 | 有意重算 CRC 的整行伪造 |
| 审计留痕 | 无意识误操作的事后追溯 | 有意篡改（无签名、无 WORM 存储） |

> 生产级方案需要：**HMAC + 密钥管理**（或只写一次存储）、
> **真实身份认证**（工牌 / AD / 双因素）、**传输加密**（TLS 1.2+）。
> 本项目**没有**这些能力，也不假装拥有。

## 3. 漏洞跟踪流程

### 3.1 定期扫描（建议流程）

```text
1. 每次发布前：在 NVD / GitHub Advisory 检索清单内所有组件
   - Qt 6.2.4 已进入 LTS 尾期，优先关注 Qt Security Advisories
   - 特别关注 Qt Quick（场景图 / QML 解析）与 QtMultimedia（外部解码器）
   - MinGW / libstdc++ 关注 GCC 安全公告
2. 记录结果到 §3.3 表格（即使「无新增漏洞」也要记录扫描日期）
3. 评估 CVSS 与是否影响本项目实际使用的模块
4. 需修复 → 走 docs/变更控制流程.md 的变更请求
```

**检索入口**：
- NVD 关键词检索：`https://nvd.nist.gov/vuln/search/results?query=Qt+6.2`
- Qt 安全公告：`https://www.qt.io/blog/security-advisories`
- GCC 安全：`https://gcc.gnu.org/security/`

### 3.2 漏洞严重度处置时限（建议）

| CVSS | 处置时限 | 动作 |
|------|---------|------|
| ≥ 9.0 | 24 小时内评估 | 若不可修复则暂停发布 |
| 7.0 ~ 8.9 | 7 天 | 修复或书面接受风险 |
| 4.0 ~ 6.9 | 30 天 | 纳入下个版本 |
| < 4.0 | 下一次例行发布 | 记录 |
