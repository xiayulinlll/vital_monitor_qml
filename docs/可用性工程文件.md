# 可用性工程文件（IEC 62366-1）

> 对应 `docs/医疗器材合规优化方向.md` **第六章**、**第三梯队第 17 项**。
>
> **适用工程**：`vital_monitor_qml`（QML 界面）。
>
> 本文按 IEC 62366-1 的**过程骨架**组织：使用场景 → 用户画像 → 任务分析 →
> 危险相关使用场景 → 界面设计对策 → 验证（目视检查表）→ 未开展的工作。
>
> ⚠️ **关键限制**：本项目**未开展任何医护人员参与的可用性测试**
> （形成性评价 / 总结性评价均无）。§7 的检查表是**工程师自查**，
> 不能替代真实用户评价。

---

## 1. 预期用途与使用环境

| 项 | 内容 |
|----|------|
| 预期用途 | 多参数生理信号（HR / SpO₂ / RR / Temp）的趋势显示与报警提示 |
| 当前实际定位 | **演示程序**，数据来自模拟器，不可用于临床 |
| 使用环境（设计假设） | 床旁 / 护士站，中距离（1~3 m）观看，环境光较强，可能有噪声 |
| 使用时长 | 长时间连续（假设 7×24 h 运行） |
| 关键约束 | 报警必须在 1 m 外可辨识；操作应在少量点击内完成 |

## 2. 用户画像

| 用户 | 目标 | 主要风险 |
|------|------|---------|
| **值班护士** | 一眼确认患者稳定；快速响应报警 | 被误报淹没 → 忽略真报警（报警疲劳） |
| **临床医生** | 查看趋势、复核报警设置 | 误改报警限而无感知 |
| **设备科工程师** | 维护、导出数据、验证日志 | 误清空历史数据 |
| （演示场景）**评审者** | 快速理解架构与设计取舍 | 误把模拟数据当真实测量 |

## 3. 任务分析（关键任务）

| 任务 | 频率 | 步骤 | 失败后果 |
|------|------|------|---------|
| T-1 启动并确认设备可用 | 每次使用 | 启动 → 看状态栏「采集运行中」 | 带故障运行 |
| T-2 识别当前患者类型 | 高频 | 看配置面板「患者类型」 | 用错报警限剖面 |
| T-3 发现并响应报警 | 高频 | 听声 / 看闪烁 → 点横幅展开列表 → 到床旁 → 确认 | 延误处置 |
| T-4 静音以暂时不想听声音 | 中频 | 点「静音」→ 视觉提示保留 | 误以为已处理 |
| T-5 暂停报警以做护理操作 | 中频 | 点「暂停」→ 操作 → 到期自动恢复 | 忘记恢复 → 报警长期被抑制 |
| T-6 调整报警限 | 低频 | 展开配置 → 改数值 → 应用配置 | 误改导致漏报 |
| T-7 复查历史数据 | 低频 | 放入 imports → 导入 → 读曲线 | 依据错误数据下结论 |

## 4. 危险相关使用场景（Use Scenarios）

| 编号 | 场景 | 危害 | 设计对策 | 对应危害分析 |
|------|------|------|---------|-------------|
| US-1 | 护士背对屏幕处理另一位患者，报警只响一次 | 漏掉持续恶化的报警 | 持续重复提示 + 超时升级 + 报警列表常驻 | H-1 |
| US-2 | 翻身导致电极脱落，数值看起来「正常」 | 未察觉信号失效 | SQI + invalid 标记 → 技术报警 + 显示 `--` | H-2 |
| US-3 | 患者活动造成单帧跳变 250 bpm | 误报警 → 报警疲劳 | 伪迹标记 → 抑制生理报警 + 技术提示 | H-3 |
| US-4 | 护士为换药暂停报警，随后忘记 | 报警长期被抑制 | 暂停有上限（危急 30 s / 普通 120 s）+ 倒计时可见 + **到期自动恢复** | H-6 |
| US-5 | 护士静音后离开，忘记自己静音过 | 只剩余视觉，远距离漏看 | 状态栏常驻「已静音」徽标 + 按钮深底提示 | H-12 |
| US-6 | 病房音量关闭 / 音频设备故障 | 完全无声，医护以为无报警 | `audioAvailable` 检测 + 横幅「无音频输出，仅视觉报警」 | H-8 |
| US-7 | 新护士不清楚当前限值，随手调大高限 | 漏报心动过速 | 🟡 有**二次确认**（列出「旧值 → 新值」，v1.2.1 起）与审计留痕；**仍无权限阻断**（QML 版未移植 `UserRole`） | H-10 |
| US-8 | 系统时间被自动校时回拨 | 报警计时失效 | 单调时钟计时 | H-5 |

## 5. 界面设计对策（已实现）

| 设计原则 | 具体实现（QML 版） |
|---------|-----------------|
| **报警可见性** | `AlarmBanner.qml` 顶部横幅：按优先级变色 + `Theme.blinkIntervalMs` 闪烁；高优先级加亮 |
| **报警可听性** | `AlarmNotifier` 分级提示音（危急 3 连响 / 900 ms，一般 1 响 / 1800 ms，提示 1 响 / 3000 ms） |
| **抑制状态可见** | 暂停：中性灰底 + 45° 斜纹 + 「恢复 N s」；状态栏常驻「报警已暂停 N s」 |
| **静音与暂停区分** | 静音 = 只关声音（闪烁保留，按钮显示「已静音」深底）；暂停 = 声光全停（横幅变灰） |
| **状态常驻** | 状态栏徽标：无报警 / N 级报警 M 条 / 已静音 / 无音频 / 已暂停 |
| **降级诚实** | 无音频时横幅右下角「⚠ 无音频输出，仅视觉报警」，不假装能响 |
| **防误操作** | 暂停按钮「暂停 ↔ 恢复」文字随状态切换；无告警时点暂停会明确提示「未生效：当前没有未确认的告警」；改报警限/量程须二次确认（v1.2.1） |
| **不掩盖异常** | 超量程显示 `↑`/`↓`，伪迹显示 `?`，不做 clamp |
| **可辨识性** | 每通道独立 Y 轴（`ChartBridge::setMultiAxis`） |
| **多报警并存** | 右侧 `AlarmListPanel` 同时列出全部活动报警（Widgets 版只有一条横幅） |
| **键盘可达** | `Space` 开始/停止、`Ctrl+A` 确认、`M` 静音、`P` 暂停（戴手套场景更可靠） |

## 6. 色码与视觉规范（IEC 60601-1-8）

| 优先级 | 颜色 | 代码 | 闪烁周期 | 声音节奏 |
|--------|------|------|---------|---------|
| 高（危及生命） | 红 | `#D32F2F` | 300 ms | 900 ms / 3 连响 |
| 中（一般告警） | 琥珀 | `#D69A09` | 550 ms | 1800 ms / 1 响 |
| 低（提示） | 青 | `#2A9EB0` | 900 ms | 3000 ms / 1 响 |

> 颜色由 `SampleData.h` 的 `alarmIndicatorColor()` 与 `qml/Theme.qml` 的
> `colorForLevel()` **两处定义但取值完全一致**；节奏由
> `Theme.blinkIntervalMs()`（视觉）与 `AlarmNotifier::soundIntervalMs()`（听觉）
> 保持一致。
>
> ⚠️ **两处硬编码是已知维护风险**：任一处改动而另一处未改，会出现
> 「横幅闪得快、声音却慢」的撕裂感。这已在 `docs/SOUP清单.md` §3 第 5 条
> 列为升级 Qt 时的必查项。

**色盲友好性**：除颜色外，另用**文字（优先级名）+ 闪烁频率 + 声音节奏**三重编码，
不只依赖色相，因此红绿色盲用户仍可区分。

## 8. 未开展的工作（IEC 62366-1 差距）

1. **未编制可用性工程计划**（Usability Engineering Plan）。
2. **未开展形成性评价**（Formative Evaluation）：应在设计早期用低保真原型
   找 ≥5 名护士做任务走查。
3. **未开展总结性评价**（Summative Evaluation）：应在真实环境用
   ≥15 名代表性用户完成危险相关任务，记录**使用错误**与**任务成功时间**。
4. **无使用错误报告收集机制**（生产后信息）。
5. **无字体 / 对比度实测**（需照度计与色度计）。
6. **未验证暂停 / 静音按钮在戴手套、强光下的可操作性** —— 这是本次新增
   两项功能（第二梯队第 6、7 项）最需要补的验证。

> 结论：本项目**具备可用性设计意识与部分对策**，但**不满足 IEC 62366-1 的过程要求**。
