# 变更控制与版本发布流程

> 对应 `docs/医疗器材合规优化方向.md` **第五章「配置管理」**、**第三梯队第 18 项**。
>
> **适用工程**：`vital_monitor_qml`。构建命令、测试目标、回归清单均为本工程实测，
> 与 Widgets 版（`vital_monitor`）不同（例如本工程没有 `compliance_test`）。
>
> 目标：任何一行代码的改动都能回答「为什么改、谁批准的、测了什么、从哪个版本到哪个版本」。

---

## 1. 版本号规则（语义化版本）

```
主版本.次版本.修订号    例：1.1.1
```

| 位置 | 递增条件 | 本项目示例 |
|------|---------|-----------|
| **主版本** | 不兼容的接口 / 数据格式变化 | 1.x → 2.0.0 |
| **次版本** | 向后兼容的功能新增（如新增静音 / 暂停、新增 SOUP 依赖） | 1.1.1 → 1.2.0 |
| **修订号** | 向后兼容的缺陷修复（不改变行为契约） | 1.1.0 → 1.1.1 |

**单一真源**：版本号只在 `CMakeLists.txt` 的 `project(vital_monitor_qml VERSION x.y.z)` 定义，
`main.cpp` 通过编译宏读取。
**禁止**在其它文件硬编码版本字符串。

> **本次（第二梯队第 6、7 项）属于次版本递增**：新增了 `AlarmNotifier`
> 与 Qt6Multimedia 依赖，属于「向后兼容的功能新增」而非纯修复。
> 因此实施后版本应为 **1.2.0**（见 `docs/CHANGELOG.md`）。

## 2. 变更分级

| 级别 | 判定 | 审批 | 验证要求 |
|------|------|------|---------|
| **A 类（安全相关）** | 触及 `AlarmDetector`、`AlarmNotifier`、`SampleData`、`AlarmBanner.qml`、`Main.qml`（报警状态与提示路径）的语义 | 至少 1 名评审人 + 逐条对照 `docs/危害分析与FMEA.md` | **两套**自动化测试全绿 + 目视回归 + 更新 FMEA |
| **B 类（功能）** | 新增通道、新面板、新的数据字段、新增依赖 | 1 名评审人 | 自动化测试 + 需求追溯矩阵更新 |
| **C 类（文档 / 样式）** | 注释、README、颜色微调 | 自审 | 构建通过 |

> 本次「静音 / 暂停 / 提示音」改动 **全部属于 A 类**：它直接决定
> 报警是否可被听到，是 C 级危害路径（见 FMEA H-6 / H-7 / H-8）。

## 3. 变更流程（6 步）

```
1. 提出变更请求（CR）
   - 填写：背景 / 变更内容 / 影响文件 / 分类（A/B/C）/ 关联需求编号
2. 风险影响分析
   - A 类必须回答：会不会引入新的危害？现有控制措施是否仍有效？
   - 更新 docs/危害分析与FMEA.md（新增行或修改残余 RPN）
3. 实现
   - 小步提交，提交信息格式见 §5
   - 同步更新文件头注释（说明「为什么」）
4. 验证
   - cmake --build --preset mingw-debug
   - ctest --test-dir build/vscode-mingw-debug --output-on-failure
   - A 类额外：手工回归 §6 清单（含静音 / 暂停项）
5. 文档同步（缺一不可）
   - docs/CHANGELOG.md
   - docs/需求追溯矩阵.md（新增 / 修改需求的验证列）
   - README.md（若涉及能力描述）
   - docs/SOUP清单.md（若升级或新增第三方组件）
   - docs/可用性工程文件.md（若涉及界面交互）
6. 发布
   - 更新 CMakeLists.txt 的 VERSION
   - 打 tag：vX.Y.Z
   - 写发布说明（改了什么 / 已知问题 / 升级注意事项）
```

## 4. 问题解决流程（缺陷处理）

```
发现缺陷
  ├─ 能复现？ → 否：记录环境与日志，标记「待复现」
  └─ 是
      ├─ 是否安全相关（影响报警 / 提示可感知性）？
      │    ├─ 是 → 立即评估是否需要回滚或热修复；A 类流程
      │    └─ 否 → 常规流程
      ├─ 写一个**失败的**测试用例（回归守护）
      ├─ 修复
      ├─ 测试转绿
      └─ 记录到 CHANGELOG 的「修复」段
```

> 「先写失败用例再修复」在本项目已多次执行。最近的实例是
> `alarm_pause_test` 用例 10「严重度变化时节奏随之改变」：
> 首版 `syncSoundTimer()` 在等级变化时只调 `start()` 而不补一声，
> 导致「升级后要等旧周期走完才变急促」。该用例**先失败、后修复**，
> 现已成为永久回归守护。

## 5. 提交信息规范

```
<类型>: <一句话说明>

背景：为什么需要这次改动（问题 / 需求编号）
改动：关键实现点（2~5 条）
验证：跑了什么（构建 / ctest / 手工回归项）
```

**类型**：`fix` / `feat` / `refactor` / `docs` / `test` / `chore`

示例：

```
feat: 新增报警分级提示音与静音 / 暂停（第二梯队第 6、7 项）

背景：QML 版此前只有横幅闪烁，没有声音、也没有静音 / 暂停，不满足 IEC 60601-1-8
改动：新增 AlarmNotifier（QSoundEffect 分级提示音、静音、暂停 + 倒计时 + 到期自动恢复）；
      AlarmBanner 增加静音 / 暂停按钮与暂停灰底斜纹；状态栏常驻报警状态徽标；
      CMake 新增 Qt6Multimedia 依赖与 alarm_pause_test
验证：cmake --build 成功；ctest 2/2 通过（alarm_state_test 13 用例、alarm_pause_test 10 用例）
```

## 6. 发布前回归清单（A 类必做）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| R-1 | 构建无警告新增 | `cmake --build --preset mingw-debug` 成功 |
| R-2 | 单元测试全绿 | `ctest` 显示 `100% tests passed`（**2 个测试目标**） |
| R-3 | 启动无 QML 报错 | 启动后无 `QML ... error` / `ReferenceError` 输出 |
| R-4 | 报警声光 | 制造越限 → 横幅变色闪烁 **且能听到分级提示音** |
| R-5 | 持续报警 | 持续越限 → 按间隔重复提示，不停止 |
| R-6 | 确认后重报 | 点确认 → 声音停 → 条件仍成立时再响 |
| R-7 | **静音** | 点静音 → 声音停 **但横幅继续闪**；再点恢复 → 声音回来 |
| R-8 | **暂停 + 倒计时** | 点暂停 → 横幅变灰 + 斜纹 + 显示「恢复 N s」→ 每秒递减 |
| R-9 | **暂停到期恢复** | 倒计时归零 → 自动恢复发声；若已无告警则保持安静 |
| R-10 | **危急暂停上限** | 危急报警下点暂停 → 最长只有 30 s（不是 120 s） |
| R-11 | **状态栏常驻** | 无报警 / 有报警 / 已静音 / 已暂停 / 无音频 五种文案都能出现 |
| R-12 | 无音频降级 | 停用音频设备后启动 → 横幅显示「无音频输出，仅视觉报警」 |
| R-13 | 报警列表排序 | 高危在前，显示持续秒数与确认状态 |
| R-14 | 审计留痕 | 暂停 / 恢复 / 静音 三类操作在审计日志中各有记录 |
| R-15 | 患者类型切换 | 切成人 / 小儿 / 新生儿 → 报警限随剖面变化，且写审计 |
| R-16 | 导出数据 | 点导出 → `exports/` 下生成 CSV / PNG |
| R-17 | 清空 | 点清空 → 曲线、告警、计数归零，声音立即停止 |

## 7. 回滚策略

- **代码**：`git revert` 到上一个 tag（本项目要求每次发布打 tag）。
- **依赖**：若回滚 Qt6Multimedia 引入，必须同时移除 `AlarmNotifier` 的
  `QSoundEffect` 使用 —— 否则链接失败（`find_package(... Multimedia)` 已改为 REQUIRED）。
- **数据格式**：历史文件加载端兼容 v1；**禁止**写出不兼容格式而不升主版本。
- **配置**：本项目配置不落盘，回滚无残留。
