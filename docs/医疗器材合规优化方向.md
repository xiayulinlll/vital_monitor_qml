### 1.2 工程优点（应保持）

在指出差距之前，先明确本项目**已经做对、且符合专业工程实践**的部分：

- **四层解耦架构**：数据采集 / 业务数据 / 绘图 / UI 层次清晰，便于测试与替换。
- **线程模型正确**：采集对象 `moveToThread()`，仅通过 `QueuedConnection` 信号槽通信，采集线程绝不触碰 UI 对象；自定义类型已通过 `qRegisterMetaType` 注册。
- **内存可控**：`RingBuffer` 定长 + `QReadWriteLock` 保护，支持长时间运行，内存上限恒定。
- **绘制性能优化**：静态网格背景预渲染缓存 + 局部重绘 + 批量提交，交互时不扰动原始数据。
- **坐标映射分离**：`CoordinateMapper` 独立维护各通道 Y 轴量程，绘图不参与业务计算。

## 二、报警系统（最高优先级）

> 报警是监护仪**最核心的临床安全功能**，也是本项目差距最大、最应优先改进的部分。
> 相关代码：`src/core/AlarmDetector.cpp`、`src/data/SampleData.h`、`src/chart/TrendChartWidget.cpp`

### 2.1 现存问题清单

| # | 缺失能力 | 标准要求 | 当前实现的问题 |
|---|---------|---------|---------------|
| 1 | **报警优先级语义** | 高 / 中 / 低三级，且需与**技术报警**（导联脱落、传感器故障）区分 | 仅 `Info/Warning/Critical`，且严重度用"超出阈值半个量程"折算（`AlarmDetector.cpp:41-42`），**非临床定义**，医护无法据此决策<br>✅ **已完成** → `AlarmPriority`（高/中/低）+ 二级危及生命阈值；**移除半量程折算**（`levelForPriority()`） |

| 4 | **报警延时可控可验证** | 报警条件延时（alarm condition delay）需量化并可验证 | `m_debounceFrames = 3` 以**帧数**计，换算时间是浮动的（10 Hz → 300 ms），缺少最坏情况论证<br>✅ **已完成** → `ChannelConfig::alarmDelayMs` 毫秒制；回归用例 4 |
| 5 | **静音 / 暂停 / 确认** | 必须具备无声、暂停功能，且有明确的**重新激活策略**与可视指示 | 无静音、无暂停、无确认机制<br>✅ **已完成** → 确认（Acknowledged + 按 `repeatMs` 重报）在 `AlarmDetector::acknowledge()`，**且已做幂等处理**；静音/暂停见 QML `AlarmBanner.qml` |
| 6 | **报警声光指示** | 听觉 + 视觉双通道，音量分级，颜色符合 IEC 60601-1-8 色码 | 仅有曲线上的三角标记，**无声音、无闪烁、无独立报警状态栏**<br>✅ **已完成** → 报警横幅 + 脉冲光晕（`pulsing`）+ 活动报警列表；颜色单一真源 `alarmIndicatorColor()` / `Theme.colorForLevel()` |
| 7 | **报警状态机** | 未确认 / 已确认 / 已静音 / 暂停 / 超时升级 | 无状态机<br>✅ **已完成** → `Active / Acknowledged / Cleared / LatchedSilent` + `Escalated` 等级（`updateCondition()`） |

### 2.2 ⚠️ 关键逻辑缺陷：告警"只报一次"

**位置**：`src/core/AlarmDetector.cpp` 第 31–54 行

```cpp
// ---- 上限判断 ----
if (cfg.hasHighAlarm && s.value > cfg.alarmHigh) {
    ++st.highCount;
    if (st.highCount >= m_debounceFrames && !st.highLatched) {  // 锁存后不再上报
        /* ... 生成一次 AlarmEvent ... */
        st.highLatched = true;
    }
} else {
    st.highCount = 0;
    st.highLatched = false;   // 只有回落到阈值内才解锁
}
```

**问题**：`highLatched` 一旦置位，**只有数值回落到阈值内才会解锁**。这意味着：

> 若患者心率持续 180 居高不下，**临床医护只会收到一次报警**，此后不再有任何提醒。

真实监护仪的报警必须是**持续性/周期性**的，直到被**确认（acknowledge）**或**报警条件解除**。这是本项目中最接近"临床危险"的一个点，建议优先修复。

> ✅ **已修复**：锁存逻辑已整体移除，改为状态机 + `alarmRepeatMs` 周期重报。
> 回归守护：`tests/alarm_state_test.cpp` 用例 1（持续越限反复上报）、
> 用例 2（确认后仍按周期重报）、用例 3（超时未确认升级）、
> 用例 11（确认与检测共用同一时基）。

### 2.4 ⚠️ 实机运行才暴露的三个缺陷（v1.1.1 已修复）

| # | 缺陷 | 现象 | 修复与回归 |

## 三、信号采集与数据完整性

> 相关代码：`src/data/VitalSignSimulator.cpp`、`src/core/RingBuffer.h`、`src/core/ChannelConfig.h`、`src/core/HistoryRecorder.cpp`

### 3.1 现存问题

| # | 问题 | 说明 |
|---|------|------|
| 1 | **无信号质量指示（SQI）** | 真实监护仪必须显示信号质量（SpO₂ 低灌注、ECG 噪声），并对低质量数据**抑制报警或标记**，以防误报<br>✅ **已完成** → `ChannelSample::quality` / `invalid`；低 SQI 抑制生理报警并改发技术报警；数值卡片显示 `--` |
| 2 | **时间戳可信性不足** | `SampleFrame.timestampMs` 用 `QDateTime`，无单调时钟保证<br>✅ **已完成（计时侧）** → 新增 `SampleFrame::monotonicMs`（`QElapsedTimer`），`AlarmDetector::frameTimeMs()` 优先取单调时钟；墙钟仅用于显示 / 存档；回归用例 10 |
| 3 | **无数据丢失检测** | `RingBuffer` 只保证容量，不检测丢帧、乱序、重复帧<br>✅ **已完成** → `SampleFrame::droppedFrames`（按**单调间隔**推算）+ 技术报警；回归用例 7 |
| 4 | **无生理合理性校验** | 缺少范围校验、变化率校验（如 HR 单帧从 60 跳到 200 应判定为伪迹）<br>✅ **已完成** → `ChannelSample::artifact`；伪迹样本不参与生理报警，**也不误报为技术报警**；回归用例 9 |
| 5 | **`clamp()` 用于数据路径有风险** | `ChannelConfig::clamp()` 直接裁剪到量程，会把真实异常值（如 HR 250）裁成量程上限，**掩盖病情**<br>✅ **已消除风险** → 数据路径**不再调用** `clamp()`（`VitalSignSimulator.cpp` 有对应说明）；`clamp()` 已加 `@warning` 明确禁止用于告警路径；越界以 `↑`/`↓` 角标呈现、伪迹以 `?` 呈现（`ChannelModel::outOfRange` / `artifact` → `ChannelValueCard.qml`） |

## 七、可靠性与健壮性

> 相关代码：`src/core/RingBuffer.h`、`src/app/MainWindowQml.cpp`、`src/data/VitalSignSimulator.cpp`、`src/main.cpp`

### 7.1 现存问题与改进点

| # | 问题 | 说明与状态 |
|---|------|-----------|
| 1 | **历史数据不持久化** | `RingBuffer` 容量固定（`60000` 帧 / `2000` 告警）→ 内存恒定（优点），但断电即丢；旧数据被静默淘汰且无提示<br>🟡 **部分完成** → 可手动导出 CSV；**定时增量落盘与淘汰提示未实现** |
| 2 | **文件损坏无容错** | 导入失败只报错，无逐行容错或部分恢复<br>🟡 **部分完成** → `HistoryRecorder::LoadStats` 会统计坏行并上报；**QML 版无 `FileIntegrity`**（导入输入校验 / 哈希清单），且导入失败直接返回，不做部分恢复 |
| 3 | **时间精度漂移** | 采样周期抖动累积未补偿<br>✅ **已完成（计时侧）** → `Qt::PreciseTimer` + 每帧记录 `monotonicMs`；丢帧数与 `deltaMs` 均由**单调时钟实际间隔**推算，告警计时不再受漂移影响。**采样周期本身未做相位补偿**（长期不会有累积误差，但单帧间隔仍可能抖动） |
| 4 | **配置快照线程安全待确认** | 主线程与 `requestUpdateConfigs` 之间共享配置快照<br>✅ **已确认安全** → 配置按值拷贝跨线程传递，`ChannelConfig` 为值类型且经 `qRegisterMetaType` 注册；采集线程只读不写 |
| 5 | **无开机自检（POST）** | 建议启动时校验缓存、文件系统、配置完整性并显示结论<br>🟡 **部分完成** → 有 `--selftest` 端到端自检（命令行、退出码即结论，本次运行 `SELFTEST PASS: frames=24 history=24 uptime=2s alarms=2`）；**但这不是开机自检**：界面上无自检结论、也不校验文件系统。Widgets 版的 `SelfTest` 未移植（FMEA H-11） |
| 6 | **无看门狗 / 心跳监控** | 建议增加采集线程心跳检测<br>🟡 **部分完成** → `AlarmDetector` 会对「采集停滞」发技术报警；**独立的看门狗定时器与自动重启未实现**（Widgets 版有，未移植；FMEA H-11） |
| 7 | **异常处理不完整** | 建议对文件 IO / 内存 / 线程启动失败建立统一处理<br>🟡 **部分完成** → 导入导出有错误返回与日志；**线程启动失败与内存分配失败无统一兜底** |
